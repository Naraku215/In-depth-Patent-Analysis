# 方法论：这套系统为什么长这样

给维护者看，不是给 agent 看的。

## 一个前提

> 如果把同一件专利丢给随便一个 AI，得到的东西不比这里好，这个项目就没有意义。

所以设计目标不是"规范产出"，而是**让产出里有裸对话给不了的东西**。

## 裸对话给不了的三样

| 东西 | 为什么给不了 | 这里怎么做 |
|---|---|---|
| **看得见的结构** | 纯文字模型只能描述，画不出可交互的三维件和带读数的工程图 | anatomy 图鉴 + 三维解剖台 |
| **数字不出错** | 上下文里数字一多，模型会串值、会把图上的读数当正文 | 先抽成 `facts.json`，产出里每个数字都要能回查 |
| **强制读图 + 说缺口** | 模型倾向只看文本、跳过附图，也倾向替专利圆场 | 流程要求逐张读图；文档必须有「证据边界」 |

这三样是**地基**，其余都是装修。

## 三层结构

```
确定性层（代码）    full.md → facts.json（权项 / 标号 / 段落 / 附图 / 数字）
生成层（模型）      图鉴、解剖台、文档 —— 只负责理解与表达
校验层（代码）      红线（准确性）+ 建议（质量）
```

关键：**确定性层与校验层不能交给模型**。模型负责"看懂"和"讲明白"，不负责记账。

## 规矩为什么分两层

早期版本把"文档必须有 8 个固定章节""引用必须是 `[00xx]` 段号"也做成硬门禁。
结果：各国专利写法不一样，模型为了让门禁通过去编段号、凑章节——**门禁本身成了失真来源**。

于是分两层：

**红线**（阻断交付）——只留"错了会把人带偏"的：

- 数字没出处
- 标号不存在
- 权项越界
- 占位符没换
- 文字损坏

**建议**（不阻断）——质量信号，改不改自己判断：

- 段号对不上、文档太短、没写证据边界、图有悬空线头、链接失效

## 为什么文档是骨架不是模具

同一套章节套在"反应器结构专利"和"两级控制方法专利"上，后者会被迫写一堆"本章不适用"。
现在只要求说清四件事：**解决什么 / 长什么样 / 权项范围 / 没证明什么**。组织方式归模型。

## 为什么图鉴要"细节不少于专利附图"

专利附图里常有人家文字不写的细节——密封方式、接管朝向、装配顺序、失败状态。
图鉴如果比原图还简略，它就没有存在价值：读者不如直接看原图。
所以标准不是"画得像"，是**信息量不低于原图，并多出"能演算"这一层**。

## 为什么一次只解析一件

批量会让每件都变浅：模型要在多件之间分配注意力，还容易跨专利串值（真发生过：把别的专利的 60% 写进钴负载）。
一件一件来，每件都能读完全部权项与附图。

## 流水线为什么是这个顺序

```
读（权项 → 背景 → 实施例 → 逐张看图）
 → 判断（值不值得画图 / 要害在哪 / 哪三个数字）
 → 图鉴（可选）→ 解剖台 → 文档
 → 校验 → 交付
```

先读后画：图的形状由专利决定。
先画后写：画的过程会逼出"文字没说清"的地方，正好补进文档。
