# 方法论：一件专利怎么被解析成一个 index

这份文档说明**为什么**流水线长这样。给维护者看，不是给 agent 看的。

---

## 一条原则

> **产出里的每个事实，都要能指回原文的一个位置。**

这条原则推导出整套设计：先做确定性抽取（`facts.json`），再让生成层只能引用抽取结果，
最后用审计引擎把"引用不上的"全部揪出来。

## 三个层次

```
┌─────────────────────────────────────────┐
│ 确定性层（代码，不靠模型）                │
│   full.md → facts.json                   │
│   段落 / 权项 / 标号 / 附图 / 数字        │
├─────────────────────────────────────────┤
│ 生成层（模型，需要判断）                  │
│   图鉴：anatomy 技能                     │
│   解剖台：三维场景 + 解读文本             │
│   文档：九节结构                         │
├─────────────────────────────────────────┤
│ 校验层（代码，不靠模型）                  │
│   audit：数字/标号/权项/段号/损坏/链接    │
│   verify：悬空线端 + headless 渲染        │
└─────────────────────────────────────────┘
```

关键：**确定性层与校验层都不能由模型代劳**。模型只负责"理解"和"表达"，不负责"记账"。

---

## 为什么是两件固定 + 一件可选

| 产出 | 必出 | 回答 | 不可替代性 |
|---|---|---|---|
| 专利解剖台 | 是 | **它长什么样、怎么装起来的** | 只有三维能表达装配关系与遮挡 |
| 专利深度解析 | 是 | **它到底主张了什么、证明了什么** | 只有文字能承载权项逻辑与证据边界 |
| 专利结构动态演算图鉴 | 否 | **它的某个原理是怎么运作的** | 只有等轴测机器图能把"物理行为"演出来 |

两类专利的差别：

- **有实体结构**（反应器、电堆、装配体、管路系统）→ 三件。图鉴补上"原理怎么动"，是解剖台看不出来的那一层。
- **没有实体结构**（纯方法、配方、参数、控制律）→ 两件。撑不起一台机器硬画，只会编出不存在的零件。

固定要解剖台，是因为"这东西长什么样"永远是理解一件专利最快的第一步；固定要文档，是因为权项范围与证据边界只有文字能承载。

## 为什么校验必须先于交付

上一轮人工解析 6 件专利 + 1 件 SOFC，最终审计出 **14 项问题**，其中 11 项是实质数值错误：

| 类型 | 例子 | 根因 |
|---|---|---|
| 数值抄错区间 | Co 负载写成 5–60%，原文 5–50% | 把别处的 60% 串了 |
| 把图读成数 | 五点 PMMA 表，实际原文只给两点 | 用图册的"感觉"补了中间值 |
| 自造约束 | 二次狭缝"10–70%"，原文只说"更小" | 为了让图更好看，编了具体比例 |
| 标号虚构 | `2 片间边条`，原文没有 2 号 | 惯例性补号 |
| 文字损坏 | `填填` `道道` `利利` | 批量替换的副作用 |

这五类全部可以机器检出，所以它们变成了 `E-NUM-UNTRACED`、`E-NUMERAL-UNKNOWN`、`E-CORRUPTION`。
**校验引擎不是附加功能，是这套系统的存在理由。**

---

## 为什么图必须"像机器"

anatomy 技能的第一条：*The object is the explanation.*

示意图（方块 + 箭头 + 标签）的问题是：它没有约束。画错了也没人知道，因为读者无从判断。
而一台机器有物理约束：零件要坐在别的零件上、流要从一个口进另一个口出、
受压会变形、转动会干涉。**约束让错误变得可见**，也让读者能"顺理成章"地理解原理。

这也是为什么图里必须有**实时读数**：读数由模型算出，指针一动就变——读者可以自己验证图没在骗人。

## 流水线为什么是七段

| 段 | 输入 | 输出 | 门禁 |
|---|---|---|---|
| 0 侦察 | 目录 | 确认输入完整 | doctor 全绿 |
| 1 抽取 | full.md | facts.json | 权项/标号非空 |
| 2 主张 | facts | notes.md | 每条能指回段号 |
| 3 图鉴 | notes + skill | atlas.html | 线端 0 / console clean |
| 4 解剖台 | notes | station.html | ≥3 视图 |
| 5 文档 | notes | doc.md | 渲染成功 |
| 6 校验 | 全部 | 内部结果（不产出文件） | **exit 0 / score 100** |
| 7 交付 | 全部 | out/<id>/index.html | 三部分齐全 |

门禁的作用：**让错误尽早暴露**。如果先写文档再画图，文档里的数字会污染图；反之亦然。
先抽取、再主张、后生成，是唯一能保证"数字只有一处来源"的顺序。

## 扩展点

- **多专利对比**：`patents/` 下放多件，`extract all` 后可写一个 `compare.mjs` 生成横向矩阵（目前未内置）。
- **换语种**：`corpus.mjs` 的标题正则已覆盖 en/de/zh；新增语种只需加一条 `CLAIM_HEADING`。
- **换图种**：`templates/figure/` 是独立于专利的，可以整包替换成别的制图技能。
- **接别的 harness**：`AGENTS.md` 是唯一需要移植的文件，其余都是 node 脚本。
