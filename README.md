# 专利解析 Agent

把一个专利文件夹，变成**一个可以点着看的 `index.html`**：三维解剖台 + 深度解读是固定两件，专利里有能确定形状的东西再加一份工程图鉴。

用于绿氢 / 燃料电池这类**系统、装置、流程、反应器**专利——目标是降低专利深度理解的成本。

---

## 用起来就三步

**1. 克隆到本地，用你的 agent 客户端打开这个文件夹**

Codex、Claude Code、WorkBuddy、Cursor 之类，只要能读 `AGENTS.md`、能跑命令就行。

**2. 把专利的两个解析文件放进 `patents/`**

```
patents/
└── 你的专利名/           ← 目录名随意
    ├── full.md            ← 专利全文（要含权利要求书）
    └── images/            ← full.md 里 ![](images/xxx.jpg) 引用的图
```

只放这两样。PDF 解析工具的其他中间产物（`layout.json`、`*_model.json`、`*_origin.pdf` 等）一个都不要——系统不读，只会让目录变臃肿。见 [`patents/README.md`](patents/README.md)。

**3. 在对话里说一句**

> 解析一下 US 10,150,093 B2

跑完在 `out/<id>/index.html`，双击就开。

---

## 会得到什么

| 产出 | 有无 | 是什么 |
|---|---|---|
| **专利解剖台** | 必有 | 按专利尺寸搭的三维模型：旋转、爆炸分解、剖切 |
| **深度解析** | 必有 | 文档。结论、结构、权项范围、证据边界、假设与简化 |
| **专利结构动态演算图鉴** | 视情况 | anatomy 等轴测工程图，指针一动读数就变 |

纯方法、纯配方、纯参数型专利撑不起一台机器，**就不画图鉴**——这时候是两件。硬画一张似是而非的机器图，比不画更糟。

---

## 凭什么比直接问 AI 强

这是这个项目唯一的立项理由。三样东西裸对话给不了：

1. **看得见的结构** —— 可交互的三维件、带读数的工程图，纯文字模型画不出来。
2. **数字不出错** —— 专利先被抽成结构化事实（全部权项、标号、段落、每个数字），产出里每个数字都要能回查；查不到的必须标成「模型值」。
3. **强制读图 + 说缺口** —— 逐张看专利附图（图里常有人家文字不写的细节），并把"专利没证明什么"单独写成一节。

---

## 规矩分两层

**红线（阻断交付）** —— 只留"错了会把人带偏"的：

- 带单位的数字查不到出处、也没标模型值
- 部件标号在专利里不存在
- 「权项 N」超出权利要求总数
- 模板占位符没替换、文字被批量替换搞坏

**建议（不阻断，自己判断）** —— 段号对不上、文档太短、没写证据边界、图有悬空线头、链接失效。

> 各国专利写法差异很大：有的没有 `[00xx]` 段号，有的权项上百项。**形式不卡人**——文档章节可增删、引用方式自选、图几张自定。系统只管准确，不管长得像不像。

## 目录

```
AGENTS.md          agent 作业手册（读这个就知道怎么干活）
CLAUDE.md / SKILL.md   给不同客户端用的入口指针
patents/           你把专利放这里
out/  work/        交付 / 中间产物（gitignored）
bin/patent.mjs     命令行
lib/               解析 / 校验 / 渲染 / 打包
prompts/           四个环节的招法
templates/         解剖台站点、图脚本、文档骨架
skills/anatomy/    vendored 的 anatomy 制图技能（MIT）
examples/          一件真实专利的完整样例（US 10,150,093 B2）
docs/METHOD.md     为什么这么设计
test/run.mjs       自检 10 项
```
