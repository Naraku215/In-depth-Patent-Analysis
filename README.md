# 专利解析 Agent

让一件专利变得**看得见、读得懂、查得实**。

专利难读，是因为结构藏在文字里、数字散在各处、主张和证据混在一起。这个项目把一件专利拆成三样东西放在人眼前，并且保证其中的每个数字都能追回原文。

---

## 怎么用

**1. 克隆到本地，用你的 agent 客户端打开这个文件夹**（Codex / Claude Code / WorkBuddy / Cursor 等，能读 `AGENTS.md`、能跑命令即可）

**2. 把专利放进 `patents/`**

```
patents/
└── 任意名字/
    ├── full.md      ← 专利全文（含权利要求书）
    └── images/      ← full.md 里 ![](images/xxx.jpg) 引用的图
```

只放这两样。PDF 解析工具的其他中间产物（`layout.json`、`*_model.json`、`*_origin.pdf` 等）系统不读。

**3. 在对话里说一句**

> 解析一下 US 10,150,093 B2

跑完在 `out/<id>/index.html`，双击就开。

## 产出

| 产出 | 有无 | 管什么 |
|---|---|---|
| **专利解剖台** | 必有 | 看得进去：可旋转、可爆炸拆解、可剖切的三维模型，右侧逐视图解读与标号表 |
| **深度解析** | 必有 | 读得明白：从"这是什么"讲到"它主张什么、没证明什么" |
| **专利结构动态演算图鉴** | 视情况 | 讲得清楚：anatomy 等轴测工程图，一张图说一件事，读数由模型算出 |

三者不是一件事的三种画法——**解剖台负责探索（入口），图鉴负责定稿（论点），文档负责通读（理解）**。

纯方法、纯配方、纯参数型专利撑不起一台机器，就不画图鉴，出两件。硬画一张似是而非的机器图，比不画更糟。

产出合在一个 `index.html` 里，三张卡片，点开即看。

---

## 凭什么比直接问 AI 强

这是这个项目唯一的立项理由。

1. **看得见的结构** —— 可交互三维件、带读数的工程图，纯文字模型画不出来。图必须比专利自己的附图信息量更大，否则不如直接看原图。
2. **数字不出错** —— 专利先被抽成结构化事实（全部权项、标号表、段落、每个数字），产出里每个数字都要能回查；查不到的必须标成「模型值」。
3. **强制读图 + 说缺口** —— 逐张看专利附图（图里常有人家文字不写的细节），并把"专利没证明什么"单独说清。

---

## 规矩分两层

**红线（阻断交付）** —— 只留"错了会把人带偏"的：

- 带单位的数字查不到出处、也没标模型值
- 部件标号在专利里不存在
- 「权项 N」超出权利要求总数
- 模板占位符没替换、文字被批量替换搞坏

**建议（不阻断，自己判断）** —— 段号对不上、文档太短、没写证据边界、图有悬空线头、链接失效。

> 各国专利写法差异很大：有的没有 `[00xx]` 段号，有的权项上百项。**形式不卡人**——文档章节可增删、引用方式自选、图几张自定。系统只管准确，不管长得像不像。

## 目录

```
AGENTS.md          agent 作业手册（读这个就知道怎么干活）
README.md          本文件
bin/patent.mjs     命令行
lib/               解析 / 校验 / 渲染 / 打包
prompts/           图鉴、解剖台的画法
templates/         解剖台站点、图脚本、文档骨架
skills/anatomy/    vendored 的 anatomy 制图技能（MIT，裁剪版 220 KB，见 UPSTREAM.md）
examples/          一件真实专利的完整样例（输入 + 产出）
test/run.mjs       自检

patents/<专利号>/   ← 输入：一件一个文件夹，里面 full.md + images/
work/<id>/          ← 加工车间：facts.json、图脚本、站点、doc.md、notes.md
out/<id>/           ← 成品：index.html + 三部分（这一个文件夹可整个发人）
```

`work/` 和 `out/` 都在 `.gitignore` 里。`work/` 是给 agent 干活用的，删掉可以重建；`out/` 是成品，可以整个文件夹拷走。
