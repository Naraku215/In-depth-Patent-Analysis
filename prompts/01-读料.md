# 阶段 1 · 抽取与读料

## 命令

```bash
node bin/patent.mjs extract
node bin/patent.mjs facts
```

`facts.json` 是确定性产出，不用你写。但**你必须读它**，否则后面每一步都会编。

## 你要产出什么

在 `work/<id>/notes.md` 写一份「读料笔记」，五块。

### 1. 它是什么
- 公开号、主题、权利人、类型（装置 / 方法 / 构件 / 用途 / 系统）
- **一句话**：这件专利解决什么问题，用什么办法

### 2. 结构骨架
- 独立权项的元件清单（a/b/c…），逐条抄原文，不要转述
- 这些元件之间怎么装在一起（谁在谁上、谁包谁）

### 3. 数字
从 `facts.numbers` 里挑出**定义性**的数字：尺寸、比例、温度、压力、时长、载量。
每个数字记三样：值 · 单位 · 出处（权项号或 `[00xx]`）。

### 4. 证据边界
专利**没有**证明什么。常见几类：
- 只有短时数据，没有寿命数据
- 只有定性描述，没有表征（SEM/XPS/称重）
- 只说"可以"，没有给实施例
- 前后数值自相矛盾（要原样记下来，不要替它圆）

### 5. 读图记录（**必做，决定后面两张图的水平**）

`node bin/patent.mjs facts` 会列出 `images/` 里的每一张图和它对应的图号。**逐张打开看**，不要只看文字。

每张图记四行：

```
图 3  剖视图  ── 画的是：管式单电池与两端密封
      图里有、文字没有：两端用 Al₂O₃ 密封胶灌封；接管是侧向插入的；引线从封头中心引出
      标号位置：1 支撑体 / 2 电流收集层 / 3 功能层 …（照图上的位置记）
      能用在：解剖台主视图 / 图鉴第 2 张
```

**关键一条**：专利附图里经常有文字不写的东西——密封方式、接管朝向、支撑与固定、剖面选取、零件之间的间隙、装配顺序、甚至失败的对比状态。这些是图鉴和解剖台真正的素材来源。**图里没有的别编，图里有的别漏。**

如果某张图看不清或信息量低，如实写「图 6 是流程图，只有方块和箭头，没有结构信息」。

## 门禁

- 每条结论都能指回权项号或段号
- 证据边界至少 2 条
- **每张附图都有一条读图记录**（`facts.images` 有几张，笔记里就有几条）
- 看到矛盾就记矛盾，不许"合理化"
