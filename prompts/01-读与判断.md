# 读与判断

目标：读完这件专利，能回答四个问题——
**它解决什么？结构或流程长什么样？它主张了什么范围？它没证明什么？**

---

## 先跑命令

```bash
node bin/patent.mjs extract
node bin/patent.mjs facts
```

`facts.json` 已经把专利拆成：全部权项、标号表、段落、每张附图、每一个数字。
**它不是参考，是地面真值**——你后面每个数字都要能在这里查到。

---

## 一、读

按这个顺序，不要跳：

1. **权利要求**（`claims`）——先看它到底要什么。独立权项的元件/步骤清单，**逐条抄原文**，不要转述。
2. **背景**（Background / 背景技术）——它说别人的方案哪里不行。这决定后面图要画什么对比。
3. **实施例**（Detailed Description / 实施例）——具体怎么做的。
4. **附图**（`facts.images` 里的每一张，逐张打开）——**这一步不能省**。

读图时每张记四行：

```
图 3  剖视图  ── 画的是：管式单电池与两端密封
      图里有、文字没写：两端用 Al₂O₃ 密封胶灌封；接管是侧向插入的
      标号位置：1 支撑体 / 2 电流收集层 / 3 功能层 …
      能用在：解剖台主视图 / 图鉴第 2 张
```

专利附图里常有文字不写的：密封方式、接管朝向、支撑与固定、零件间隙、装配顺序、失败的对比状态。**这些是后面两张图最值钱的素材。图里有的别漏，图里没有的别编。**

---

## 二、判断（不写进任何产出，自己心里过一遍）

1. **这件专利有没有"能确定形状"的东西？** 能不能指着某个部件说"这是它长什么样"？
   - 能 → 图鉴值得做
   - 只能确定"几步之间怎么连" → 不做图鉴，或者把关键装置画实、其余用接口表示
   - 只有配方/参数/控制律 → 不做图鉴
2. **要害在哪条权项？** 独立权项通常范围最宽但特征最虚；真正的限定常在从权或性能参数里。找出"被告要绕开，必须改哪一个特征"。
3. **哪三个数字最能定义它？** 尺寸、比例、温度、压力、时长、载量——每个都能指回原文。

---

## 三、写进 `work/<id>/notes.md`

```markdown
## 一句话
它解决什么问题、用什么办法。

## 结构骨架
独立权项的元件（照抄原文）：
(a) … (b) … (c) …
它们怎么装在一起：…

## 关键数字
| 值 | 单位 | 出处 |

## 读图记录
图 1 …（每张一条）

## 证据边界
- 没有证明：…
- 没有证明：…
```

**门禁**：每条结论能指回权项号/段号/章节名；证据边界 ≥ 2 条；每张附图都有读图记录。
看到原文自相矛盾的地方，**照录并标注**，不要替它圆。
