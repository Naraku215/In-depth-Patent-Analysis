# 专利解剖台

解剖台是这套系统的核心产出：把专利的结构做成**可以拆开看的三维模型**。

## 动手前：先把附图看透

解剖台的形状来自两处：**文字描述**和**专利附图**。附图往往更准。

从阶段 1 的「读图记录」里取这几样：

- **剖视图 / 轴测图**：直接对应零件的截面形状与相对位置；
- **标号在图上落在哪**：决定 `report.js` 里 parts 表能不能对上；
- **文字没写但图上有的**：密封方式、接管朝向、支撑与固定、零件间隙、装配顺序；
- **哪张图最适合做第一个视图**：通常是总装剖视图。

**图里画了、你就得建；图里没画、别自己补。** 判断不了的写「原文未给」。

## scenes.js：几何

### 场景注册

```js
A.scenes.p1 = {
  id: 'p1',
  code: 'US 10,150,093 B2',
  short: '微结构反应器 · 蒸发冷却',
  patentee: 'INERATEC / KIT · 2018 授权',
  tag: '装置',
  views: [
    { id: 'stack',  label: '叠层解剖', build: viewStack },
    { id: 'field',  label: '冷却场',   build: viewField },
    { id: 'dist',   label: '分配层',   build: viewDist },
  ]
};
```

### build(b) 里能用的东西

| 调用 | 作用 |
|---|---|
| `b.group(name, {explode:[dx,dy,dz]})` | 注册可爆炸的组；`explode` 是拉到 100% 时的位移 |
| `b.box(x0,x1,y0,y1,z0,z1, style, group)` | 轴对齐长方体 |
| `b.line([p…], {stroke,sw,alpha,dash}, group)` | 折线 |
| `b.tube([p…], r, style, group, seg)` | 管线 |
| `b.label([x,y,z], '文字', {color,dx,dy,anchor,group})` | 标号 |
| `b.flow({path, count, speed, color})` | 流动粒子 |
| `return makeScene(b, {view:{}, tick:fn})` | 收尾，`tick` 每帧回调 |

坐标：`+x` 右、`+y` 里、`+z` 上。

### 视图设计

- **3–5 个视图**，每个回答一个问题（整体怎么装 / 关键层怎么工作 / 流怎么走 / 怎么装配）
- 每个视图都要有 `explode`：拉杆一动，能看见里面
- 每个视图都要有 `tick` 或 `flow`：至少一处动起来
- **不要**把整台机器塞进一个视图——分层解剖才是"解剖台"

## report.js：文字

```js
A.patents.p1 = {
  title: '…',            // ≤ 30 字
  abstract: '…',         // 3–4 句，讲清问题与解法
  facts: [['申请人','…'], ['授权','…'], ['权项','N 项']],
  claim: '权项 1 的要害…'
};

A.notes['p1:stack'] = {
  key: '叠层解剖',
  title: '…',
  body: ['第 1 段…', '第 2 段…'],
  parts: [['1','…'], ['2','…']],   // ← 标号必须来自 facts.numerals
  tags: ['…']
};
```

## 标号纪律

`parts` 里每个编号必须能在 `facts.numerals` 里找到。没有标号的部件，写成描述（"上隔板"），**不要自己编号**。

审计会查：`E-NUMERAL-UNKNOWN`。

## 验收

```bash
node bin/patent.mjs build <id>
node bin/patent.mjs verify <id>
```
门禁：`悬空线端 0`、`console clean`、`statViews` 不是 `—`（说明脚本跑起来了）。
手动检查：拖动旋转是否流畅、爆炸拉杆是否每层都动、剖切是否正确露出内部。
