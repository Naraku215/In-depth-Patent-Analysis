# 图鉴（可选）

## 先判断做不做 —— 判断要松

不是"只有讲装置/设备的专利才能画"。判据是**专利有没有给出一个足够具体的、可确定形状的系统或装置**：

- 讲某个**设备**（反应器、电堆、测试台、换热器）——有结构就做。
- 讲某个**系统或工艺**，但里面有一套确切的设备、且有附图或文字描述其构造——**也做**。把成套设备（或其中关键的一段）画出来，比只画方块图有用得多。
- 只有流程方块、没有可确定形状的东西——不做。

判断句：**能不能从文字或附图里确定"这东西长什么样"？** 能，就做；只能确定"几步之间怎么连"，就不做，或者只画到能确定的那一层（关键装置画实，其余用接口表示）。

**别为了凑数硬画，也别因为专利标题是"方法"就轻易放弃。**

---

## 底线：图鉴的细节不能少于专利附图

这是这一阶段最重要的标准。

专利附图里画出来的东西——标号怎么摆、谁连着谁、哪里是剖面、装配顺序、密封与固定的方式——**如果图鉴比它还简略，那这张图就不值得存在**。

做法：
1. 先看阶段 1 的「读图记录」，把每张专利附图的**信息点**列出来（结构、连接、朝向、间隙、剖面、状态对比）。
2. 决定图鉴要覆盖其中哪几条，在图里**都能找到对应**。
3. 图鉴可以在"能演算"上加分（会动的读数、可比较的两种状态），但**不允许在结构细节上退步**。

做不到，就少画一张，而不是画一张更模糊的。

## 每张图的要求

### 选材：一张图只讲一件事
1. **构件级的物理行为**（受压、膨胀、折弯、流动）——做成一台试验台/压机；
2. **装配关系**（层序、密封、连接）——做成爆炸视图；
3. **工艺流程**（多级、循环、再生）——做成一台流程装置。

不要在一张图里塞两件事。2–4 张即可。

### 尺寸必须来自专利
`fig-01.mjs` 顶部有一块 `/* ---- 1. 尺寸 ---- */`，每个常量后面写注释标明出处：
```js
const CH_W = 1.0;      // 通道宽 [0018]
const CH_H = 6.5;      // 波高 [0032]
```
图上没有出处的尺寸只能是三种：底座厚度、装饰圆角、画布间距——这三类不写注释。

### 必须有的东西
- **底座**：一台放在工作台上的机器，脚下要有脚/垫
- **支撑关系**：每个零件都坐在别的零件上，没有悬空
- **真实读数**：`readout` 里的数字由 `script` 里的模型算出来，指针一动就变
- **图例**：3 条 `keys`
- **说明**：`caption` 里写清这台装置哪部分来自专利、哪部分是示意，**并点明参考了哪几张附图**

### 读数纪律
- 专利给了的：直接用，caption 里标出处；
- 专利没给的（模型算的）：caption 里写「读数说明：…为该模型算出的值，专利未给具体数值」。
  注意 anatomy 的 `plateHtml` 会转义 HTML，所以**不要用标签**。

### 禁止
- 悬空线头（`verify` 会查）
- 没有支撑的浮空零件
- 图里写大段文字（只允许一个极小的 FaceText）
- 用颜色表达含义（颜色只用于材质）

## 做之前先自查一遍

对着阶段 1 的读图记录问：

- [ ] 专利附图里的**关键结构**，图里有对应吗？
- [ ] 附图里出现过、文字没写的细节（密封、接管、支撑、间隙、装配顺序），我画了吗？
- [ ] 我加的东西，每一个都有出处（专利或公认通用件）吗？
- [ ] 有没有哪个零件是我为了"看起来完整"而编的？

答不上来就先别画。

## 编页

改 `atlas.mjs` 顶部 `FIGS` 数组与 `INTRO` 里的 `{{KICKER}}` `{{H1}}` `{{LEDE}}`。
`{{LEDE}}` 里写明「参考专利附图 图 n / 图 m」。
